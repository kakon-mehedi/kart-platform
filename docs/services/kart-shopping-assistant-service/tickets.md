## Epic: kart-shopping-assistant-service v1 — the Kart Shopping Assistant

A new, independently deployed bounded context (ADR-0028, the platform's 20th deployable repo), built in FastAPI/Python (ADR-0030) — a `Customer`-facing (and guest-eligible for read-only intents), **mutating** GenAI orchestrator across nine existing bounded contexts (`kart-order-service`, `kart-cart-service`, `kart-offer-service`, `kart-search-service`, `kart-product-service`, `kart-recommendation-service`, `kart-user-service`, `kart-delivery-tracking-service`, `kart-wishlist-service` — never `kart-payment-service` directly). It owns exactly three local structures — `ShoppingAssistantSession` (Redis, ephemeral), `ShoppingAssistantAuditRecord` (Postgres, append-only), `ShoppingAssistantIdempotencyKey` (Postgres) — and never becomes a second owner of any downstream service's domain data. Zero published/consumed events (`event-contract.md`).

Four categories of ticket appear below, per this pipeline stage's own instructions for this run:

- **Section A — Foundation & scaffolding (SA-1–SA-23).** Project/CI/Docker scaffolding, the new `kart_shared` Python package (no prior Python art on this platform, ADR-0030), migrations + RLS, Redis session store, the query endpoint, and the cross-cutting mechanisms (registry, auth gate, confirmation state machine, grounding, circuit breakers, audit) every per-intent ticket in Section B builds on.
- **Section B — One ticket per catalogued intent (SA-24–SA-38, 15 tickets across requirement-spec.md §2's 12 rows).** Three gap-affected rows (1, 8, 9) are split into a buildable "now" ticket and a **blocked** "full" ticket, rather than bundling buildable and blocked work into one PR-sized unit — see each pair's own note. Row 10 gets exactly one ticket, per this run's own instruction, since its full v1 scope (escalation, never a fabricated replacement) is entirely buildable now.
- **Section C — Cross-service prerequisite tickets, filed against the owning service.** Three confirmed, load-bearing gaps (Architecture-1/`kart-order-service`, Data-1/`kart-offer-service`, Data-2/owner-TBD) plus one small Identity config addition (ADR-0029) — referenced here by the target repo's own ticket-ID convention, **not written into those repos' own `tickets.md` files by this pass**; see this section's own header note and the closing report for why.
- **Section D — Integration/E2E tickets (SA-39–SA-50).** Exercise every unblocked intent against real staging instances of its backing service(s), per this run's own commissioning goal of a real, working application — never a mocked demo.
