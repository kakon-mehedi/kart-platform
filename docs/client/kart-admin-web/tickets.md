**Notes specific to this addition:**
- No dedicated accessibility/design-system-compliance ticket is added for this feature area. ## Notes for Sprint Planner Agent

- **AUTH-3 (idle-session state machine) is the single shared foundation**, analogous to `kart-admin-service/tickets.md`'s ADM-1 — every feature ticket in `catalog-management`, `order-exceptions`, `support-console`, `identity-admin`, and two of three `audit-compliance` tickets depend on it directly for session/role context (the interceptor that attaches the session cookie, the tab-active flag the silent-refresh interceptor reads, and the role claim every route guard reads). AUTH-4 and AUTH-5 both depend only on AUTH-3, not on each other, and can proceed in parallel once it lands.
- **AUTH-5 (category-grant UI gating) is the second shared foundation** nearly every write-capable feature ticket needs (all of `catalog-management`, all of `identity-admin`, `order-exceptions`, `support-console`, and AUD-3). AUD-1 and AUD-2 are the two exceptions — `AdminActionPerformed`'s audit viewer is a coarse role gate only, no per-category grant check applies (`kart-admin-service/api-contract.yaml`'s own note on `GET /admin/actions`), and the analytics dashboards similarly read from `kart-analytics-service`'s `InternalBI` path rather than a category-gated admin-write endpoint — so both can start as soon as AUTH-3 lands, without waiting on AUTH-5.
